A Fourier transform tells you not just that a bearing is failing, but where

A bearing with a defect gets a small knock every time a ball rolls over it. The knocks come at a rate set by the bearing's geometry, so a Fourier transform turns them into peaks at frequencies you can compute in advance. Put a tracker on each of those frequencies and watch which one rises. The data streams in live, simulated in your browser.

Tune the detector, and how it works

Each snapshot is 0.2 seconds of vibration sampled at 20 480 Hz, a hundred snapshots per run. Each knock rings the bearing housing at its resonance, so the signal is squared to recover the knock rhythm, and a Fourier transform of that gives the envelope spectrum. A tracker sums the energy in a narrow band around its fault frequency and second harmonic, as a share of the whole spectrum, so a louder machine does not look like damage. The first 30 snapshots set what normal looks like, using the median and MAD. After that a CUSUM test per tracker adds up how far each snapshot sits above normal, minus the allowance k, and raises the alarm when the sum passes h. The tracker that crosses first names the fault.

The vibration strip holds 409 600 samples. Drawing them all would be slow, so they are kept in a min/max mipmap: each level stores the minimum and maximum of pairs from the level below, updated as each snapshot streams in. The strip picks the level where one entry covers about one pixel, so drawing costs the same at every zoom. Fully zoomed in, it draws the raw samples.

How I approach a monitoring problem

  1. Start from the physics. Know what a fault looks like before looking for it.
  2. Keep a few meaningful features. Normalised, so a gain change does not look like damage.
  3. Learn healthy, robustly. One odd reading should not move the baseline.
  4. Test sequentially. Small deviations add up before a single reading looks wrong.
  5. Report in the plant's language. A plot an operator can read, a warning time in hours, and what the model cannot see.
